# 风格化 3D：人物控制、跟随相机与风格化渲染

在 olib_sample 根目录运行 `run.bat stylized3d`。按 [Celeste64](https://github.com/ExOK/Celeste64) 一帧的结构，
用 Render3D 验收渲染机制。草、花、树冠、石块与木箱均为程序生成的几何，资产与代码都不取自 Celeste64。
光照、雾和描边的外观都在 `shaders/` 里，属于本示例；olib 只提供下面这些机制。

- WASD / 方向键：按相机方向移动；Shift：加速；空格：跳跃。
- 按住鼠标右键拖动：绕角色旋转相机；滚轮：拉近 / 拉远；R：重置人物与相机。
- P：暂停（包括风）；O：开关环境光遮蔽；L：开关太阳阴影；E：开关深度描边；Esc：退出。窗口可任意缩放。
  原来的 A 与空格分别改为左移、跳跃，AO 和暂停开关迁到 O、P。
- `shot` 用固定时间画一帧，把最终合成（含 UI）写到 `library/screenshots/stylized3d.png` 后退出；
  `shot flat` 关掉描边，写 `stylized3d_flat.png` 便于对比；`size=1366x768` 指定窗口尺寸。
  `shot noao` 只关掉 AO，写 `stylized3d_noao.png`；可与 `flat` 组合，写 `stylized3d_flat_noao.png`。
  `SDL_GPU_DRIVER=vulkan` / `direct3d12` 选后端。
- `shot follow` 用游戏初始跟随视角截图，写 `stylized3d-follow.png`。
  `shot follow calm` / `shot follow gust` 固定在 0 / 7 秒，对比微风与阵风，写 `stylized3d-calm.png` / `stylized3d-gust.png`。
  `shot follow noshadow` 关闭太阳阴影，写 `stylized3d-noshadow.png`。
  `shot water` 使用池塘展示机位，写 `stylized3d-water.png`；加 `noreflection` 输出无倒影对比 `stylized3d-water-flat.png`。
  `shot camera` 复现人物紧贴墙背、低角度镜头开始抬升的第一帧，写 `stylized3d-camera.png`，并检查取景距离与镜头碰撞。
  `smoke` 自动移动、跳跃、转相机并把窗口调整到 1366×768，检查碰撞并写 `stylized3d-controller-smoke.png`。

## 人物与相机

`controller.odin` 是本示例的运动学控制器，不依赖物理引擎。角色脚底为位置原点，
使用直立圆柱和场景旋转包围盒碰撞，支持贴墙滑动、0.3 单位以下自动上台阶、跳上平台、顶头和落地。
方块碰撞体与可见网格共用变换；树冠使用保守的实体包围盒，并非精确球面。
速度为 4.2 / 6.5，重力 22，起跳速度 9；带 0.10 秒离地宽限和 0.12 秒跳跃输入缓冲。
物理按 120 Hz 固定步进，帧间输入归一化，避免斜走加速；失焦和暂停时释放鼠标并清除待处理跳跃。

第三人称相机平滑跟随角色，缩放范围 3–12；镜头实体使用扩大的旋转盒和地形检测，给近平面保留空间。
视线遮挡与镜头实体碰撞分开处理：墙挡住人物时维持取景距离，人物被遮挡的部分显示剪影，
低墙上方能获得无遮挡视角时平滑抬高俯视角。高墙无法越过时保留请求角度，避免一直俯冲到人物头顶。
只有镜头位置本身进入物体时才收近，若会小于 3 单位则优先寻找较高的安全位置；
恢复距离时也检查中间位置，离开障碍后平滑拉远。小地图保持北向上并跟随人物。
`player_render.odin` 负责朝向与简单步行动画，角色圆影会落在脚下的平台上。
普通运行已移除自动左右移动；`shot` 仍保留固定的遮挡展示机位，以便比较 AO 与描边。

CPU 回归测试：

```sh
odin test src/stylized3d -collection:olib=../olib -vet
```

覆盖相机相对移动与斜向速度、旋转碰撞体、撞墙滑动、跳跃落地与禁止二段跳、顶头、台阶、
离开平台、跳跃缓冲、相机避障 / 恢复、30 / 144 FPS 下固定步进的一致性、太阳投影的覆盖范围和深度映射，
以及不同机位与宽高比下水面反射的投影对齐、地形网格与碰撞高度一致性、人物沿池岸进出 / 跳跃落地、相机避开池岸。
相机回归还覆盖高墙遮挡保持距离、低墙抬升过渡首帧不贴脸、镜头在实体内时抬高避让，以及天花板碰撞后的平滑恢复。

## 草地、实例与阵风

暖色泥土小径穿过草地，沿路留出空地；草、花、分层树冠、石块和木箱细节使用统一的黄绿、赭石与蓝紫阴影配色。
静态场景按石木构件、树冠、岩石、树干、草、花分为六个常驻 GPU 实例缓冲，初始化时只上传一次。
池塘区域清除草花并补充水边草后共 1036 个静态实例；主画面、小地图、太阳阴影和倒影复用这些缓冲，具体绘制次数随机位裁剪及透明排序变化。
不同位置、尺寸和颜色复用网格与材质，太阳阴影通道直接复用同一实例缓冲；人物保留动态实例。

`shaders/MeadowWind.hlsli` 在顶点阶段按世界位置和时间计算风，每约 14 秒一轮，起始时刻和强弱略有变化。
阵风以每秒 4.5 世界单位沿固定方向掠过，在单个位置持续约 3.8 秒，随后衰减回摆；平时只有很轻的微风。
草根和花茎底部固定，越靠尖端弯曲越明显，树冠幅度更小。`Tangent.w` 标记草（-1）、树冠（-2）、花（-3），
其余几何保持 +1，不受风影响。颜色和太阳深度通道共用同一变形函数，树冠与投影同步，CPU 无须逐帧更新实例。
风只影响外观，人物碰撞体保持稳定；可在该文件调整周期、传播速度和各类植物的振幅，然后重新生成 Shader。

太阳阴影使用跟随人物、按阴影纹素对齐的 2048² 正交深度图与 3×3 PCF，覆盖 48 世界单位。
树、石块、墙、木箱和人物投影；小草和花只接收阴影，避免细碎阴影和额外绘制。

## 波光与实时倒影

小径左侧的浅水池使用 `water.odin` 与 `shaders/Water.oshader`。草地基准高度为 0，水面为 -0.38，池底最深处为 -0.95。
原平面地面替换成实际凹陷的地形网格，池塘附近细分、远处保持平面，坡岸自然连接草地与池底。
外观参考 [Core Keeper 的水边实机画面](https://images.nintendolife.com/screenshots/152122/large.jpg)：深蓝水体、细碎的蓝色亮纹和有层次的岸壁。
池塘轮廓采用四次超椭圆，地形、水面与植被避让保持一致；水边草复用常驻草实例批次与风动画。
岸坡露出分层赭色土壤，近水处有深色接触线；水面由坡岸遮挡形成实际岸线，带浅水渐变和断续水纹。
水纹按世界坐标每单位 24 格量化，以每秒 8 次相位更新，叠加短横纹、缓慢移动的破碎焦散和稀疏亮点。
倒影混入较深的蓝色并适当减弱，让场景倒影融入水体。
水波使用场景时钟，P 暂停时与草地的风一起停下。

每帧将主相机的位置和目标绕水面镜像，以场景分辨率绘制独立的颜色 / Depth32 目标，
复用六个常驻实例缓冲和人物当前姿态，包含天空、树木、石块、建筑、人物与金币。
反射视图裁掉水下几何、跳过水面本身及人物剪影，贴地圆影不参与反射；正常光照和树冠风动画保持同步。
水面按世界坐标投影采样倒影纹理，视角转动时倒影保持对齐；小地图只显示池塘底色和水纹。
窗口缩放会重新创建并绑定倒影目标。倒影增加一次场景绘制，未测量 GPU 耗时。

地形网格、人物支撑高度、贴地圆影和相机避障共用 `terrain_height()`。
人物可以沿坡岸走入池底，再走回草地；岸边岩石的位置和碰撞一起贴合地形。水深约 0.57，可涉水，未添加游泳物理。
`POND_CENTER` / `POND_RADIUS` 控制位置和范围，同时决定草花的避让区域。
水色、高光和扰动幅度可在 Water Shader 中调整；`noreflection` 可检查没有实时倒影时的水面。

## 一帧

1. 先提交 `shadow` 到太阳阴影 Target（颜色 + Depth32），再绘制镜像相机的倒影 Target，最后开始主场景 Target。场景约 360 像素高：按窗口高度取整数放大倍数，宽高向上取整铺满窗口，
   最近邻放大后多出的不足一个放大像素被裁掉，任何窗口尺寸都没有黑边。窗口变化时重建目标并重新绑定深度贴图。
2. 同一份记录按 Pass id 分阶段提交：`sky` → `scene` → `silhouette` → `body`。
   剪影（`ZTest Greater`、不写深度）要在遮挡物写完深度之后、角色本体写深度之前画，
   否则会叠到角色自己被挡住的部位上。场景材质与角色用不同的 Pass id，才能把两者拆开提交。
3. 环境光遮蔽与深度描边：先用 AmbientOcclusion 材质增强接触处，再用 DepthEdge 描边，各自把场景颜色画到 post，材质里的 `_depth` 由
   `material_set_texture` 绑定场景的深度附件。深度附件不能在仍是当前深度目标时采样，
   所以先画到另一张 Target，再拷回场景，场景深度留给后面的半透明物体。
4. `water` 在不透明场景的后处理完成后绘制并写入深度；随后 `transparent` 绘制贴地圆影（Blob）与金币（Billboard，沿视图块里的相机轴展开），读场景深度、不写深度。
5. 小地图：同一份记录提交给俯视相机，视图块不同（不加雾、相机轴不同），金币朝向俯视相机。
6. 合成在最终窗口像素尺寸进行；小地图与 HUD 贴窗口角落，按窗口高度相对 720 缩放，不随低分辨率场景放大。

外观（属于示例）：背光面混向偏蓝紫的阴影色而不是变黑，掠射角加轮廓光；雾色与天空地平线相同，远处地面融进天空。

## 环境光遮蔽

`shaders/AmbientOcclusion.oshader` 用深度重建视空间位置和法线，在 8 个方向、每个方向 4 个距离上估算遮蔽。
游戏在 `startup()` 将世界半径设为 0.65、强度设为 1.15，集中加强墙根、箱子堆叠和树冠交接处，阴影略偏冷。
固定采样不引入随机噪点；法线选择深度更接近的相邻像素，减少轮廓处错误遮蔽。
天空和屏幕外采样被排除，超出半径的几何不参与遮蔽，远景随原场景雾淡出。
这是基于可见深度的近似，屏幕外和被完全遮住的物体不会贡献 AO。

AO 与描边复用 post 目标，不增加常驻纹理；开启 AO 会增加一次后处理及一次颜色回拷。
窗口变化时同步更新深度绑定、像素尺寸和投影比例。AO 在半透明物体、小地图与 HUD 之前完成，
保持金币、剪影提示和界面易读；不单独处理小地图。运行时参数在 `startup()` 调整，Shader Lab 的预览默认值来自 shader 的 Properties。

## 视图块

`View.globals` 是游戏按 std140 打包的字节，Model Pass 从顶点 b1 / 片元 b2 读取，最多 1024 字节，不足补零。
本示例的布局是 `main.odin` 的 `Scene_View`，与 `shaders/Stylized.hlsli` 的 `SceneView` 一一对应：

```odin
globals := scene_view(s, &camera, fog = 1) // 太阳、阴影色、雾、相机轴、太阳投影
view := r3d.View{target = scene, view_projection = world.camera3d_view_projection(&camera),
	view_matrix = world.camera3d_view(&camera), globals = mem.ptr_to_bytes(&globals)}
err := r3d.submit(&renderer, view, "scene")
```

太阳与雾放在视图块里，所有材质都能读到，不必逐个材质 `material_set_number`；
布局共 17 个 float4（272 字节）：原始光照 / 雾 / 相机轴后接太阳投影四列与阴影参数，
再接倒影投影四列与水面高度、反射裁剪标志、主视图标志、倒影开关。
相机轴必须逐视图，不能放在材质参数里（同一份记录会提交给多个视图）。
Shader Lab 预览提交全零，`scene_view()` 据 `sun_color.a == 0` 换成默认值，同一份 Shader 不改就能预览。

## Shader

改了 `shaders/` 下的源码后，在 olib_sample 根目录重新生成 `Compiled/`（需要 PATH 上的 SDL_shadercross）：

```sh
odin run ../olib/tools/shaders -- -dir:src/stylized3d/shaders
```

Shader Lab 可直接预览和热重载这些 Shader：`run.bat shader_lab source <绝对路径>/src/stylized3d/shaders`。
